# 常见问题

[English](../troubleshooting.md) · [全部文档](README.md)

先在问题发生时读取状态：

```js
console.log(voice.getState());
```

使用后端管理的通话，通常应看到 `media: connected`、`agent: running` 和 `audio: running`。
它们分别描述通话的不同部分，不能只靠这三个值判断 AI 的声音一定已经播放出来。

## AIUI Agent 连不上

| 现象                | 先检查                                                                    |
| ------------------- | ------------------------------------------------------------------------- |
| `UNSUPPORTED`       | Ink 是否支持 WHIP、WebRTC、音频和麦克风。只在普通浏览器安装这个包还不够。 |
| `BACKEND`           | 服务是否启动、地址是否能访问、Authorization 是否符合后端认证要求。        |
| 浏览器请求被拦截    | HTTPS 和 `ALLOWED_ORIGINS`，填写 Web 宿主的准确来源。                     |
| `MICROPHONE`        | 宿主和系统是否都允许录音，输入设备是否可用。                              |
| `MEDIA` / `TIMEOUT` | Agora WHIP 地址、项目开通状态、网络、频道和 JWT 有效期。                  |
| AI 启动失败         | 后端的 App ID、Certificate、区域、pipeline ID，以及云端响应。             |

手机上的 `127.0.0.1` 指手机本身，请使用设备可以访问的 HTTPS 后端。
失败后重新创建 session，重复使用旧对象不会重试。

## 已连接，但听不到 AI

1. 确认 `audio` 是 `running`。如果暂停，将 Ink 带回前台，点击示例中的恢复按钮，
   或在用户操作时调用 `resumeAudio()`。
2. 检查扬声器静音、SDK 音量、系统音量和输出设备。
3. 说话时观察本地音量条。不动时检查麦克风选择与静音状态。
4. 预期 AI 回答时观察远端音量条。有电平却听不到，优先排查播放；没有电平还需继续定位。
5. 在 Studio 中测试同一个已发布助手，确认语言和发音服务工作正常。

如果自己管理凭证，请使用同一频道、客户端**字符串 UID**，以及另一个 AI 字符串 UID。
设置 `enable_string_uid: true`，并在 `remote_rtc_uids` 中订阅准确的客户端账号，
见[身份与凭证](backend.md#身份与凭证)。参考后端会自动配置。

没有欢迎语不一定是问题，有些 pipeline 需要用户先说话。
`agent: running` 只表示启动请求已确认，不会持续监测 AI 是否正常运行。
必要时结合 `getStats()` 的收包情况与云端对话记录排查。包数增加也不能单独证明有可听到的语音。

## AI 说到一半就停了

先看停止瞬间的 `audio` 和 `media`：

- **`audio: suspended`**：宿主暂停了本地音频。回到前台，再点击恢复。
  此时媒体连接仍可能保持已连接。
- **`media: disconnected`**：媒体路径中断，等待恢复；彻底失败后会结束会话，
  需要重新创建 session 连接。
- **播放和媒体都正常**：分别对比佩戴耳机、在一次 AI 回答期间关闭麦克风的情况，
  帮助区分播放或失焦问题、声音回到麦克风，以及云端轮次打断。
  调整配置前，先检查 pipeline 的打断设置和云端记录。

单凭停顿无法判断原因。原生示例中出现的回答提前截断仍在排查，见[验证范围](validation.md#真实云端验证)。

## 为什么通话一段时间后结束？

查看 `error.code`，尤其是 `LEASE`。
参考后端需要定期续约，默认通话上限为 30 分钟，启动 AI 时设置了 60 秒空闲超时。
这些与媒体连接状态、凭证过期是不同的事情。
需要其他时长时，请调整后端策略和云端配置。

## 必须在电脑上一直运行后端吗？

本地参考测试需要。正式部署时，改为你自己的 HTTPS 服务。
如果已有系统负责启动 AI、签发临时凭证，可以[直接连接](integration.md#使用已有临时凭证)，
运行时不依赖会话后端。签名证书仍应保留在可信服务端。

## 能否增加字幕、消息和工具调用？

SDK 通过 RTM 接收实时 ASR 和 AI 回复，收到中间结果就显示，不轮询历史记录。
与播放逐字同步的字幕、通用聊天消息发送、AI 语义事件和本地工具执行需要额外接入。
建立音频连接不会自动建立消息通道。

## ASR 出字慢

先检查 `getTranscriptState().status`。已连接时，客户端会显示 RTM 推送的中间结果，
不会等待 `final: true` 才出字。首次出字仍受识别语言、模型处理、上行音频缓冲和网络时延影响。
识别语言应与用户匹配，例如中文 ARES 使用 `asr.language: 'zh-CN'`。
部分供应商的 `asr.params.language` 会覆盖这个设置。
应调整会话或 pipeline 的 ASR 配置，不要用历史轮询或人为逐字动画掩盖识别延迟。

## 向开发者或声网反馈时，提供什么？

提供 SDK 版本、Ink 宿主及构建、操作系统、复现步骤、带时区的时间，以及故障前后的状态快照。
声网协查时，再提供频道和后端从云端启动响应获得的 **`agent_id`**。
本地预留会话的 `id` 与云端 `agent_id` 是两个不同标识。

不要附带 App Certificate、访问 token 或模型密钥。
SDK 不会自动采集日志，也不会通过 `getState()` 暴露云端 Agent ID。
