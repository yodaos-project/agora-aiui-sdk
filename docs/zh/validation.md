# 开发与验证

[English](../validation.md) · [全部文档](README.md)

这页面向贡献者，以及准备确认 SDK 是否满足项目需求的开发者。
第一次使用，请先看[入门指南](getting-started.md)。

## 运行本地检查

使用 Node.js 22+，在仓库根目录执行：

```sh
npm ci
npm run check
npm run example:prepare
npm pack --dry-run
```

`check` 包含单元测试、TypeScript 类型声明检查和 Prettier 格式检查。
测试覆盖启动与取消、延迟结果、立即停止录音、清理超时、连接状态、音频控制、
租约续期、HTTP 认证、响应大小限制和后端并发场景。
官方 Agora 服务端 SDK 的请求通过本地模拟接口验证，不访问真实云端。

`example:prepare` 将客户端复制进示例 AIUI Agent。
`npm pack --dry-run` 列出发布包内容，包中不应包含服务端代码或凭证。

修改文档时，请同步中英文页面，检查相对链接和标题锚点，并对照当前 API 核对代码示例。
文档是直接在 GitHub 阅读的 Markdown 文件，没有独立文档站点需要构建。

## 可选的 Ink Web 检查

示例在 `transcripts` Agent Worker 中加载 RTM 及其 Wasm。原生 Ink 会使用独立线程，
音频和界面仍留在 Page。Ink Web 的 Worker realm 目前仍共享浏览器主事件循环，
因此这次改动不代表 Web 已支持 CPU 任务离开主线程。原生与 Web 性能需要分别验证。

准备 Chrome/Chromium，以及包含 WHIP 支持的 Ink Web 构建后：

```sh
INK_WEB_DIST=/absolute/path/to/ink/packages/ink-web/dist npm run test:ink
```

测试使用虚拟麦克风，以 448 × 170 彩色和单绿主题渲染示例，并检查 480 × 352 的彩色布局，
并在 Ink JavaScript 运行环境中检查 SDK 启动与清理。
认证会在请求外部 WHIP 之前主动失败。
需要保存示例截图时，将 `INK_TEST_SCREENSHOT` 设为 PNG 文件的绝对路径。

这是运行时冒烟测试，不访问 Agora，也不能证明真机上一定能听到 AI。

## 真实云端验证

截至 **2026-10-29**，已测试的云端语音路径统一使用字符串账号。
Ink 和 AI 使用同一频道中的两个不同 UID。

| 宿主或测试              | 已观察到的结果                         | 范围                                                  |
| ----------------------- | -------------------------------------- | ----------------------------------------------------- |
| 原生 Chrome WHIP 对照   | 收到并解码真实 AI 回答。               | 浏览器对照组，不是 Ink 客户端。                       |
| Ink Web + 本 SDK        | 多次语音输入并解码 AI 回答。           | 虚拟麦克风，真实 Agora 云端和 Ink 运行环境。          |
| 原生 `ink-open` 示例    | 用户确认两端均能听到，能进行语音对话。 | 基础人工验收；回答提前截断的反馈仍在排查。            |
| Android / 眼镜 + 本 SDK | 尚需重新进行物理设备验收。             | 之前的人与人 WHIP 通话不能代替本 SDK 的云端 AI 验证。 |

一次 120 秒的 Ink Web 测试完成了三轮用户与 AI 对话，并在关闭前接收了第四次用户输入。
最后一次采样记录了 6,556 个上行 RTP 包和 5,514 个 AI 下行包。
这次运行没有加载 Agora RTC SDK，也没有额外观察者入会。
媒体、麦克风、音频和云端清理均完成。

这些结果只适用于当时测试的地址、pipeline 和宿主构建，不能代表所有设备、网络和配置的可靠性。
请使用自己的部署完成下面的验收。

**2026-10-30**，原生 `ink-open` 还通过 RTM 收到了真实 ASR 中间结果和流式 AI 回复，
不轮询历史记录，也不依赖本地中转服务。
固定账号连续两次真实登录、订阅、注销复用了同一个客户端。
用户确认，轮流说话的示例不再把 AI 播放声音或回答期间的插话混入下一句识别结果。
这里使用的是半双工收音控制，不是原生回声消除；需要等 AI 说完再讲话，
也不保证特定的 ASR 首字时延。

在 **2026-11-01**，macOS 的 release 版 `ink-open` 已通过 Agent Worker 运行 RTM，
连接真实 Agora Cloud。一次 176 秒通话收到 305 次 ASR 更新。在包含 ASR 活动的
30 个四秒观测窗口中，Page 动画回调约为每秒 59.7–60.0 次，最大的窗口 p95 间隔为
20.3 ms，最大帧间隔为 34.5 ms；统计排除了启动、停止和音频暂停的窗口。
用户确认说话和插话均流畅。额外两轮同账号连接、停止测试中，麦克风、WHIP、
云端 AI 和 RTM 均完成清理。这些是原生端结果，不代表 Web 或 Android 的性能。

## 在目标宿主上验收

1. 从用户操作发起连接，允许麦克风。
2. 检查媒体、云端启动确认、音频播放三个状态。
3. 问几个不同问题，听完 AI 的完整回答，至少包含一次较长回答。
4. 确认本地和远端音量条分别跟随对应的语音变化。
5. 测试麦克风静音、扬声器静音、音量调节，以及切换应用后返回。
6. 结束通话，确认录音停止，后端停止云端 AI。
7. 取消启动、关闭页面，确认后端能回收遗留会话。
8. 在目标桌面、Web、Android 或眼镜宿主上分别重复。

保留测试时间和后端记录的云端 `agent_id`，便于协查。
反馈时提供状态快照和复现步骤，不附带证书、token 或模型密钥。
失败时参考[常见问题](troubleshooting.md)。
